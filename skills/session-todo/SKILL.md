# Session Todo — 工作任務管理

## 觸發對照

| 使用者說 | 流程 |
|----------|------|
| 開工 / start work | 流程一：開工 |
| 收工 / end work | 流程二：收工 |
| 打完收工 | 流程五：快速收工（全部完成，無互動） |
| 停工 | 流程六：強制收工（任務維持現狀，無互動） |
| 任務清單 / 目前進度 | 流程三：顯示任務 |
| 討論任務 | 流程四：討論任務 |

---

## 流程一：開工

1. **確認 todo/ 目錄**：不存在則詢問是否建立
2. **計算 Session 編號**：`ls todo/*.md 2>/dev/null | wc -l`，編號 = 數量 + 1
3. **帶入上次未完成**：讀最新 md 檔，從「⏸ 未完成」與「📝 下次待辦」兩個區塊收集所有 `- [ ]` 項目合併帶入；若最新檔無收工時間，提示先收工
4. **從 Apple Reminders 拉取待辦**：
   ```bash
   osascript -e 'tell application "Reminders" to get name of reminders of list "工作" whose completed is false'
   ```
   有輸出 → 顯示編號清單讓使用者選擇；選取的加 `[R]` 前綴帶入；說「不用」→ 跳過
5. **建立 Session 檔案**：檔名 `todo/YYYY-MM-DD_HH-MM.md`，寫入標題與任務清單
6. **回覆**：顯示 Session 編號、時間、本次任務清單（附編號）

---

## 流程二：收工

1. **找進行中 Session**：`ls -t todo/*.md | head -1`，確認無 `🕐 收工：` 行；有則提示先開工
2. **互動確認完成**：列出任務（附編號），問「哪些完成了？（說 1 2 / 全部 / 都沒有）」，等待回覆
3. **詢問下次任務**：「下次還需要做什麼？（或說沒有了）」；若有 PRD 參照 `references/prd-integration.md`
4. **更新 Session 檔案**：
   - `## ✅ 已完成`：`[x]` 項目
   - `## ⏸ 未完成（移至下次）`：`[ ]` 項目
   - `## 📝 下次待辦`：使用者補充的下次任務
   - 最後一行：`🕐 收工：HH:MM`
5. **同步完成狀態回 Apple Reminders（必須執行，不可略過）**：
   - 找本次 session 所有 `- [x] [R] 任務名稱` 行（`[x]` 與 `[R]` 之間有空格）
   - 去掉 `[R] ` 前綴，對每筆**實際執行**：
     ```bash
     osascript -e 'tell application "Reminders" to set completed of reminder "任務名稱" of list "工作" to true'
     ```
   - 執行失敗 → 繼續下一筆，摘要標 `⚠️ 找不到：任務名稱`
   - 未完成的 `[R]` 任務不做操作
6. **回覆收工摘要**：顯示完成項目、未完成項目、下次待辦、檔案路徑

---

## 流程三：顯示任務清單

1. 讀最新 2-3 個 session 的 md 檔
2. 顯示：進行中 session 的目前任務、最近已完成的摘要、未完成積壓（全部附編號）

---

## 流程四：討論任務

1. 讀最新 session 待辦；載入 `references/prd-integration.md`；尋找 PRD 文件
2. 討論後續優先順序、拆解任務，確認後更新「📝 下次待辦」區塊

---

## 流程五：打完收工（快速）

執行流程二，跳過所有互動：所有 `[ ]` 直接標 `[x]` → 同步 Reminders（同 Step 5）→ 寫入收工時間 → 輸出摘要

---

## 流程六：停工（強制）

執行流程二，跳過所有互動：任務狀態維持原樣 → 同步已完成 `[R]` 回 Reminders（同 Step 5）→ 寫入收工時間 → 輸出摘要

---

## 硬性規則

- `todo/` 目錄一律在**當前工作目錄**（不是 ~/.claude/）
- 每次開工建立**一個新的 md 檔**，不覆蓋舊檔，不刪歷史
- Session 以「每次開工/收工」為單位，與日期無關，同天可有多個
- 未明確告知哪些完成 → **必須逐項詢問**，不自動假設
- 寫入前先讀取最新版本，避免覆蓋衝突
- **收工時必須執行 Apple Reminders 同步**，即使沒有 `[R]` 任務也要確認後才跳過
- 回覆給使用者的任務清單一律加上編號（`1.`、`2.`...）；md 檔內部仍用 `- [ ]`
