# Todo Session 檔案格式規範

## 檔名規則

```
todo/YYYY-MM-DD_HH-MM.md
```

範例：`todo/2026-04-29_14-30.md`

- 使用開工的日期時間（24 小時制）
- `-` 分隔年月日，`_` 分隔日期與時間，`-` 分隔時分
- 同天多個 session 自然依時間排序不衝突

---

## 進行中的 Session（未收工）

```markdown
# Session #3 — 2026-04-29 14:30 開工

## 🎯 本次任務
- [ ] 撰寫 API 文件
- [ ] 測試登入流程
- [ ] 修復購物車 bug
```

---

## 已收工的 Session（完整格式）

```markdown
# Session #3 — 2026-04-29 14:30 開工

## ✅ 已完成
- [x] 撰寫 API 文件
- [x] 測試登入流程

## ⏸ 未完成（移至下次）
- [ ] 修復購物車 bug

## 📝 下次待辦
- [ ] 繼續購物車 bug
- [ ] 新增訂單通知功能

🕐 收工：16:45
```

## 格式說明

### Session 標題
- `# Session #N — YYYY-MM-DD HH:MM 開工`
- N 從 1 開始，每次開工遞增（跨天繼續計數，不重置）

### 任務狀態符號
| 符號 | 意義 |
|------|------|
| `- [ ]` | 待完成 |
| `- [x]` | 已完成 |
| `- [-]` | 取消/不做了 |

### 各區塊用途
| 區塊 | 出現時機 | 說明 |
|------|----------|------|
| `🎯 本次任務` | 開工後、收工前 | 本次 session 的目標 |
| `✅ 已完成` | 收工時寫入 | 本次完成的項目 |
| `⏸ 未完成（移至下次）` | 收工時寫入 | 本次未完成，自動帶入下次 |
| `📝 下次待辦` | 收工時寫入 | 使用者規劃的下次新任務 |

### 收工時間
- 最後一行：`🕐 收工：HH:MM`（只寫時分，不重複日期）
- 這一行是「是否已收工」的判斷依據

---

## 帶入未完成任務的邏輯

開工時，從上一個 session 的兩個區塊收集待辦：
1. `⏸ 未完成（移至下次）`：所有 `- [ ]` 項目
2. `📝 下次待辦`：所有 `- [ ]` 項目

兩者合併後，作為新 session 的 `🎯 本次任務` 初始內容。
若兩者都空，本次任務區塊留空，提示使用者補充。
