# PRD 整合指南

## 尋找 PRD 文件

依序在當前工作目錄尋找（不限定副檔名）：

1. `./PRD.md`
2. `./prd.md`
3. `./docs/PRD.md`
4. `./docs/prd.md`
5. `./PRD.txt`
6. `./REQUIREMENTS.md`
7. `./requirements.md`

若以上都找不到，詢問使用者：「找不到 PRD 文件，請問 PRD 在哪裡？（可提供路徑）」

---

## 從 PRD 提取任務建議

讀取 PRD 後，執行以下分析：

### 1. 識別功能清單
找出 PRD 中所有明確列出的功能項目、需求條目、User Story、或 Acceptance Criteria。

### 2. 比對已完成項目
掃描 `todo/` 目錄下所有 session 的 `✅ 已完成` 區塊，建立已完成功能清單。

### 3. 找出差距
找出 PRD 中提及、但尚未出現在任何 session 的功能項目。

### 4. 主動建議
以清楚格式呈現建議：

```
📋 根據 PRD，以下項目尚未排入任務：

高優先（PRD 核心功能）：
- [ ] 功能 A
- [ ] 功能 B

中優先（PRD 第二階段）：
- [ ] 功能 C

你要把哪些加入下次任務？
```

---

## 討論任務的原則

1. **先聽使用者說** — 詢問「這次想做什麼？」，不要直接推送 PRD 任務
2. **補充而非取代** — 使用者說完後，再補充 PRD 中可能遺漏的相關項目
3. **主動拆解大任務** — 若使用者說「做登入功能」，幫他拆成可執行的子任務：
   - [ ] 建立登入頁面 UI
   - [ ] 撰寫登入 API
   - [ ] 驗證 token 邏輯
   - [ ] 錯誤訊息處理
4. **讓使用者決定優先順序** — 提供建議，不強迫按 PRD 順序
5. **估計規模** — 可選擇性地提示任務大小（小/中/大）幫助規劃 session 目標
