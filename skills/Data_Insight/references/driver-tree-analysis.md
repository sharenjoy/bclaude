# 驅動因素樹分析框架 (Driver Tree Analysis)

> 將複雜的業務指標拆解為可操作的驅動因素，找到真正的增長槓桿。

---

## 一、什麼是驅動因素樹

### 核心理念

驅動因素樹（Driver Tree）是一種將頂層KPI **逐層分解** 到可操作因素的分析方法。

```
目標：不是只看"收入下降了"
而是：找到"收入下降是因為哪個環節出了問題，應該從哪裡改進"
```

### 為什麼要用驅動因素樹？

| 只看頂層指標 | 使用驅動因素樹 |
|-------------|---------------|
| 收入下降10% | 收入下降10% = 客單價↑5% × 訂單量↓15% |
| 不知道從哪改進 | 訂單量下降來自新客減少，需要加強獲客 |
| 只能給出模糊建議 | 可以量化每個因素的貢獻度 |
| 容易遺漏關鍵因素 | 系統性覆蓋所有驅動因素 |

## 二、經典驅動因素樹模型

### 1. 收入驅動樹 (Revenue Driver Tree)

```
收入 (Revenue)
│
├─ 用戶量 (Users)
│   ├─ 新用戶
│   │   ├─ 自然流量
│   │   ├─ 付費獲客
│   │   └─ 轉介紹
│   └─ 老用戶留存
│       ├─ 留存率
│       └─ 召回用戶
│
├─ 轉化率 (Conversion)
│   ├─ 瀏覽→加購率
│   ├─ 加購→下單率
│   └─ 下單→支付率
│
└─ 客單價 (ARPU)
    ├─ 件單價
    ├─ 購買件數
    └─ 購買頻次
```

**基礎公式**：
```
收入 = 用戶數 × 轉化率 × 客單價
     = 用戶數 × 轉化率 × 件單價 × 件數 × 頻次
```

### 2. 利潤驅動樹 (Profit Driver Tree)

```
利潤 (Profit)
│
├─ 收入 (Revenue)
│   └─ [參考收入驅動樹]
│
└─ 成本 (Cost)
    ├─ 可變成本
    │   ├─ 商品成本 (COGS)
    │   ├─ 物流成本
    │   └─ 支付手續費
    │
    └─ 固定成本
        ├─ 人力成本
        ├─ 營銷費用
        └─ 運營費用
```

**關鍵指標**：
```
毛利率 = (收入 - 可變成本) / 收入
淨利率 = (收入 - 總成本) / 收入
```

### 3. 用戶增長驅動樹 (Growth Driver Tree)

```
用戶淨增長
│
├─ 新增用戶 (Acquisition)
│   ├─ 渠道A新增
│   │   ├─ 曝光量
│   │   ├─ 點擊率
│   │   └─ 轉化率
│   ├─ 渠道B新增
│   └─ 自然增長
│
├─ 用戶留存 (Retention)
│   ├─ 次日留存
│   ├─ 7日留存
│   └─ 30日留存
│
└─ 用戶流失 (Churn)
    ├─ 主動流失
    └─ 自然流失
```

**增長核算公式**：
```
期末用戶 = 期初用戶 + 新增 - 流失
淨增長 = 新增用戶 - 流失用戶
```

### 4. 電商GMV驅動樹

```
GMV
│
├─ 流量 (Traffic)
│   ├─ 搜索流量
│   ├─ 推薦流量
│   ├─ 活動流量
│   └─ 付費流量
│
├─ 轉化率 (CVR)
│   ├─ 詳情頁轉化
│   ├─ 加購轉化
│   └─ 支付轉化
│
├─ 客單價 (ATV)
│   ├─ 商品均價
│   └─ 連帶率
│
└─ 復購 (Repurchase)
    ├─ 復購率
    └─ 復購頻次
```

### 5. SaaS業務驅動樹

```
MRR (月經常性收入)
│
├─ 新增MRR
│   ├─ 新客戶
│   │   ├─ 線索量
│   │   ├─ 轉化率
│   │   └─ 客單價
│   └─ 老客戶升級
│
├─ 流失MRR
│   ├─ 客戶流失 (Churn)
│   └─ 降級收入
│
└─ 擴展MRR
    ├─ 追加購買
    └─ 交叉銷售
```

**SaaS關鍵指標**：
```
淨收入留存率 (NRR) = (期初MRR + 擴展 - 流失 - 降級) / 期初MRR
LTV = ARPU × 平均生命週期
LTV/CAC > 3 為健康
```

## 三、如何構建驅動因素樹

### Step 1: 確定頂層目標

明確你要分析的核心KPI：
- 收入/利潤/GMV
- 用戶數/活躍度
- 轉化率/留存率

### Step 2: 識別第一層驅動因素

問自己：這個指標由哪些 **相乘或相加** 的因素構成？

```
乘法關係：收入 = 用戶 × 轉化 × 客單價
加法關係：用戶 = 新用戶 + 老用戶
```

### Step 3: 繼續拆解每個因素

對每個一級因素重複Step 2，直到：
- 因素已經是可直接操作/可直接獲取數據的
- 繼續拆解沒有業務意義

### Step 4: 驗證完整性 (MECE檢驗)

- **相互獨立**：各因素之間不重疊
- **完全窮盡**：所有因素加起來等於上級

### Step 5: 標註數據可得性

| 因素 | 數據來源 | 可得性 |
|-----|---------|-------|
| 新用戶數 | 用戶表 | ✅ 可得 |
| 競品價格 | 市場調研 | ⚠️ 需採集 |
| 用戶滿意度 | 調研問卷 | ❌ 暫無 |

## 四、驅動因素歸因分析

### 量化每個因素的貢獻

當頂層指標變化時，要量化每個因素的貢獻度。

#### 乘法分解法

對於 `Y = A × B × C` 的結構：

```
收入變化 = (用戶變化貢獻) + (轉化率變化貢獻) + (客單價變化貢獻)

簡化計算：
用戶貢獻 ≈ Δ用戶/用戶基數 × 原收入
轉化貢獻 ≈ Δ轉化/轉化基數 × 原收入
客單價貢獻 ≈ Δ客單價/客單價基數 × 原收入
```

#### 實例演示

```
Q2 vs Q1 收入變化分析：

Q1: 收入 = 10000用戶 × 5%轉化 × 200元客單價 = 100萬
Q2: 收入 = 9000用戶 × 6%轉化 × 220元客單價 = 118.8萬

收入增長 = +18.8萬 (+18.8%)

因素拆解：
- 用戶下降貢獻：(9000-10000)/10000 × 100萬 = -10萬
- 轉化提升貢獻：(6%-5%)/5% × 100萬 = +20萬
- 客單價提升貢獻：(220-200)/200 × 100萬 = +10萬
- 交叉項：約 -1.2萬

結論：雖然用戶流失帶來10萬損失，但轉化率和客單價的提升
     彌補了用戶損失，整體收入仍增長18.8萬。
```

### 敏感性分析

識別哪個因素對結果影響最大（槓桿最高）：

```
當前狀態：收入 = 10000用戶 × 5%轉化 × 200元

各因素提升10%的影響：
- 用戶+10%：收入 → 110萬 (+10%)
- 轉化+10%：收入 → 110萬 (+10%)
- 客單價+10%：收入 → 110萬 (+10%)

但實際可提升空間不同：
- 用戶+10%：需要增加1000獲客，成本約5萬
- 轉化+10%：優化頁面，成本約0.5萬
- 客單價+10%：可能導致轉化下降

結論：轉化率優化是ROI最高的槓桿
```

## 五、常見業務場景驅動樹

### 場景1：銷售下滑診斷

```
銷售額下滑
│
├─量的問題？
│   ├─ 客戶數下降？
│   │   ├─ 新客減少
│   │   └─ 老客流失
│   └─ 購買頻次下降？
│
├─ 價的問題？
│   ├─ 主動降價？
│   ├─ 產品結構變化？（低價產品佔比上升）
│   └─ 折扣力度加大？
│
└─ 渠道問題？
    ├─ 線上渠道
    └─ 線下渠道
```

### 場景2：利潤率下降診斷

```
利潤率下降
│
├─ 收入端
│   ├─ 價格下降？
│   └─ 產品結構惡化？
│
└─ 成本端
    ├─ 原材料漲價？
    ├─ 人力成本上升？
    ├─ 營銷費用增加？
    └─ 運營效率下降？
```

### 場景3：用戶活躍度下降診斷

```
DAU下降
│
├─ 新用戶問題
│   ├─ 獲客量下降
│   └─ 新用戶激活率下降
│
├─ 老用戶問題
│   ├─ 留存率下降
│   └─ 回訪頻次下降
│
└─ 流失加速
    ├─ 產品問題
    ├─ 競品分流
    └─ 需求變化
```

## 六、驅動因素樹最佳實踐

### DO - 應該做

1. **從業務邏輯出發**，而不是從數據出發
2. **保持MECE**，確保不重不漏
3. **標註數據可得性**，識別數據缺口
4. **量化因素貢獻**，不只是定性描述
5. **識別關鍵槓杆**，聚焦高ROI因素
6. **定期更新**，業務變化時重構驅動樹

### DON'T - 避免

1. **過度拆解**：拆到沒有業務意義的層級
2. **遺漏關鍵因素**：只看容易量化的，忽略難量化但重要的
3. **混淆層級**：把不同層級的因素放在同一層
4. **忽略交叉影響**：因素之間可能相互影響
5. **只建不用**：建完驅動樹但分析時不用它
