# 假設驅動分析法 & So What 追問鏈

> 大師級數據分析師的核心思維方式：不是"看看數據說什麼"，而是"用數據驗證假設、驅動決策"。

---

## 一、假設驅動分析法 (Hypothesis-Driven Analysis)

### 核心理念

```
普通分析師：拿到數據 → 做各種分析 → 看看能發現什麼
大師分析師：明確問題 → 提出假設 → 用數據驗證 → 得出結論
```

### 為什麼假設先行？

| 漫無目的分析 | 假設驅動分析 |
|-------------|-------------|
| 耗時長，容易迷失 | 聚焦，高效 |
| 輸出一堆"有趣但無用"的發現 | 輸出可行動的結論 |
| 分析完不知道該幹什麼 | 直接指向決策 |
| 容易被數據"牽著走" | 主動掌控分析方向 |

### 執行步驟

#### Step 1: 明確核心問題 (Define the Question)

**追問清單**：
- 這個分析要回答什麼業務問題？
- 分析結果會影響什麼決策？
- 誰是這個分析的受眾？他們關心什麼？
- 如果分析結論是 A，會怎麼做？如果是 B，又會怎麼做？

**問題重構技巧**：
```
用戶說的          →  真正需要回答的
"分析一下銷售數據"  →  "找到銷售增長的機會點"
"看看用戶行為"     →  "識別高價值用戶的特徵"
"出個月報"        →  "診斷本月業績問題並給出建議"
```

#### Step 2: 構建假設樹 (Build Hypothesis Tree)

將核心問題拆解為可驗證的子假設：

```
核心問題：為什麼 Q3 銷售下滑？
│
├─ 假設1：需求端問題
│   ├─ 1.1 市場整體萎縮
│   ├─ 1.2 競品搶佔份額
│   └─ 1.3 用戶需求轉移
│
├─ 假設2：供給端問題
│   ├─ 2.1 產品競爭力下降
│   ├─ 2.2 定價策略問題
│   └─ 2.3 供應鏈/庫存問題
│
└─ 假設3：渠道端問題
    ├─ 3.1 線上渠道流量下降
    ├─ 3.2 線下經銷商流失
    └─ 3.3 營銷投放效率降低
```

#### Step 3: 確定驗證方法 (Design Validation)

每個假設都要明確：
- 需要什麼數據來驗證？
- 數據從哪裡獲取？
- 什麼樣的結果能證實/證偽假設？

| 假設 | 所需數據 | 證實標準 | 證偽標準 |
|-----|---------|---------|---------|
| 市場整體萎縮 | 行業報告、競品數據 | 行業增速<0 | 行業增速>0 |
| 競品搶佔份額 | 競品銷量/市佔率 | 競品份額↑且我方↓ | 競品份額無明顯變化 |
| 定價策略問題 | 價格變動、價格彈性 | 提價後銷量顯著下降 | 價格與銷量無相關性 |

#### Step 4: 執行分析 (Execute Analysis)

- 按優先級驗證假設（先驗證最可能的、影響最大的）
- 記錄每個假設的驗證結果
- 保持開放心態，允許假設被推翻

#### Step 5: 綜合結論 (Synthesize Findings)

```
經過驗證，Q3銷售下滑的主要原因是：
✓ 假設3.2 成立：華東區3家核心經銷商流失，貢獻了60%的下滑
✗ 假設1.1 不成立：行業整體增長5%，我方逆勢下滑
△ 假設2.2 部分成立：高端線提價影響了10%的銷量
```

## 二、So What 追問鏈

### 核心理念

> 數據本身沒有價值，數據背後的洞察和行動才有價值。

每個數據發現都要經過三層追問：

```
數據現象 → So What? → 業務含義 → So What? → 行動建議 → So What? → 預期影響
```

### So What 追問示例

#### 示例1：銷售分析

```
Level 0 - 數據現象：
"Q3銷售額同比下降15%"

↓ So What?

Level 1 - 業務含義：
"下降主要來自華東區（貢獻80%降幅），其中經銷商渠道下滑最嚴重"

↓ So What?

Level 2 - 根因分析：
"3家核心經銷商因賬期問題終止合作，導致該區域覆蓋率從85%降至60%"

↓ So What?

Level 3 - 行動建議：
"建議：1)與流失經銷商重新談判賬期 2)緊急開發2家替代經銷商 3)臨時增加直營配送"

↓ So What?

Level 4 - 預期影響：
"預計執行後Q4可恢復華東區70%銷量，減少損失約500萬"
```

#### 示例2：用戶分析

```
Level 0："月活用戶增長20%"
↓ So What?
Level 1："增長主要來自下沉市場，一線城市用戶實際在流失"
↓ So What?
Level 2："下沉用戶ARPU僅為一線用戶的1/5，總收入實際下降"
↓ So What?
Level 3："需要差異化運營：下沉市場做規模，一線城市做價值"
```

### So What 檢驗清單

每個結論都用這個清單檢驗：

- [ ] **可理解**：非專業人士能聽懂嗎？
- [ ] **有對比**：比什麼高/低/快/慢？
- [ ] **有歸因**：為什麼會這樣？
- [ ] **可行動**：基於這個結論應該做什麼？
- [ ] **可量化**：行動的預期收益是什麼？

### 常見的"偽結論"

| 偽結論 | 問題 | 改進 |
|-------|------|------|
| "銷售下降了15%" | 只有現象，沒有分析 | 下降來自哪裡？為什麼？ |
| "用戶滿意度有待提升" | 空泛，無法行動 | 哪些維度不滿意？改進優先級？ |
| "建議加強營銷投入" | 方向不明確 | 投入哪個渠道？預期ROI？ |
| "數據表明A和B相關" | 沒有業務含義 | 這個相關性意味著什麼？如何利用？ |

## 三、實戰模板

### 分析啟動檢查清單

在開始任何分析之前，確認：

```markdown
## 分析啟動檢查

### 1. 問題定義
- [ ] 核心業務問題是什麼？
- [ ] 這個分析支持什麼決策？
- [ ] 受眾是誰？他們的關注點？

### 2. 假設構建
- [ ] 列出3-5個初始假設
- [ ] 假設之間是否MECE？
- [ ] 每個假設的驗證方法？

### 3. 數據準備
- [ ] 需要哪些數據？
- [ ] 數據是否可獲取？
- [ ] 數據質量如何？

### 4. 成功標準
- [ ] 什麼樣的結論是"好結論"？
- [ ] 如何衡量分析的價值？
```

### 結論輸出模板

```markdown
## [結論標題 - 一句話概括]

### 核心發現
[用2-3句話說清楚發現了什麼]

### 數據支撐
- 關鍵數據點1：xxx
- 關鍵數據點2：xxx
- 對比基準：xxx

### 根因分析
[為什麼會出現這個現象]

### 行動建議
1. [具體行動1] - 預期效果：xxx
2. [具體行動2] - 預期效果：xxx

### 風險與假設
- 本結論基於以下假設：xxx
- 主要不確定性：xxx
```

## 四、思維轉變要點

### 從"分析師"到"問題解決者"

| 分析師思維 | 問題解決者思維 |
|-----------|---------------|
| 我有什麼數據 | 我需要回答什麼問題 |
| 數據呈現什麼 | 數據意味著什麼 |
| 分析做完了 | 決策者能行動了嗎 |
| 這個發現很有趣 | 這個發現能帶來什麼價值 |

### 記住

> "The goal is not to analyze data, but to drive decisions."
>
> 分析的目標不是分析數據本身，而是驅動決策。
